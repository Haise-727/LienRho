- **LangChain**: backend re-implements parts it shouldn't.
- **LangGraph (ai/nexus)**: functional API is the correct choice for our sequential flow, not overkill.

## HIGH (fix now)
### H1 — routes.py:71-72 date bug
`_invoice_out` hardcodes `invoice_date=""`, `due_date=""`, so the action queue and summaries drop real dates (the investigation endpoint uses real dates). Fix: pass `invoice.invoice_date/due_date`.

### H2 — Tripled decision logic
`strategist.recommend()`'s verdict is discarded; `build_action_queue` re-derives A/B/C via `engine.decide_action` AND direct rule calls (`service.py:267-315`, `strategy.py:156`, `engine.py:85`). Three copies of the same A/B/C logic; the strategist output is mostly dead. Fix: make the strategist the single decision source; have `build_recommendation` consume `strategy.recommendation`; drop the direct rules calls.

## MEDIUM
- **M1** `service.py` (~573 LoC) god-module doing queue-build, approvals, investigations, drafts, artifacts, forecasts, findings -> split into queue/investigation/artifacts services.
- **M2** ~900 LoC dormant LLM/agent layer (investigator, strategist, LiteLLMChatModel, MockLLMClient, langfuse) is dead when `llm_enabled=False` -> speculative overengineering; trim or gate behind a feature flag.
- **M3** `llm_client.py:327,343` re-implements `bind_tools`/`with_structured_output` that LangChain's `BaseChatModel` already provides (fragile `json.loads` parse) -> use native `with_structured_output`.
- **M4** Two LLM seams: backend `LLMClient` vs `ai/nexus/llm.complete` -> diverging infra (gateway/virtual-keys/langfuse); Nexus cannot reuse backend's infra and will silently diverge. Unify on the backend seam.
- **M5** `ai/` is not an installable package; `sys.path` bootstrap in `main.py:7-8` + `conftest.py:6-7` + dual manifests (`pyproject.toml` vs `ai/requirements.txt`) -> fragile for IDEs/mypy/other entrypoints. Make `ai` a workspace package or fold nexus into backend; drop the sys.path hack.
- **M6** Two settings objects (backend `Settings` vs `ai` `NexusSettings`, NEXUS_ prefix) reading the same `.env` -> consolidate (nest Nexus under backend Settings, keep prefix for isolation if desired).
- **M7** `communications.py:360` `PROMISE_HISTORY` process-global dict holds promise reliability that DB/invoice history should own; investigator reads global state instead of persisted data -> derive from payments or store on Customer.
- **M8** `store.py:143,152` hand-rolls `model.org_id == org_id` instead of reusing `db/scoping.py:69 org_scoped` -> use the sanctioned helper.
- **M9** "rule+LLM fallback" agent pattern duplicated across backend (LangChain) and ai (LangGraph) without a shared base -> document the split as intentional and extract a common "rule+LLM fallback + settings gate" base to prevent drift.

## GENUINELY GOOD (keep)
- Integer-paise wire contract (kills IEEE-754 drift that flips the 3-bps demo winner).
- Text-only LLM boundary (financials never derived from the model) — consistent in both backend and ai/nexus.
- `MatchingClient` seam (clean dependency inversion toward Track 2).
- FastAPI layering, fail-fast prod-secret guard (`config.py:84`), tenant isolation via signed token + composite PK (`db/models.py:38`) and `Principal` dependency, durable audit-trail design.
- Frontend: server/client split (token never reaches browser), OpenAPI-generated types with drift guards, no domain math in components, small presentational components, `ArtifactView` correctly uses `<pre>` over a Markdown renderer.
- Strong tests (24 backend files; 15 ai).

## Reinventing-the-wheel scorecard
- Backend re-implements LangChain `with_structured_output`/`bind_tools` -> REAL reinvention.
- Two parallel LLM abstraction layers (backend `LLMClient` vs ai `llm.complete`) -> mechanism duplication.
- Two agent stacks (LangChain agents vs LangGraph functional) for overlapping "rule+LLM fallback" -> justified by separate domains (recovery vs marketplace) but mechanism duplicated.
- Global dict used for data that should be persisted (`PROMISE_HISTORY`) -> reinventing a DB.
- ai/nexus itself is NOT reinventing the domain (marketplace clearing is new); its LangGraph choice is appropriate.

## Spaghetti / overengineering scorecard
- Dormant LLM layer = the largest overengineering.
- `service.py` god-module = spaghetti risk.
- ai/nexus many tiny modules (config/llm/matching/providers/prompts) = acceptable separation, not overengineering.
- Frontend = not spaghetti.

## Prioritized fixes (top down)
1. H1 date bug (tiny, high user impact).
2. H2 collapse duplicated decision logic into one strategist source.
3. M5 package `ai` properly / kill sys.path hack.
4. M4 + M6 unify LLM seam + settings across backend and ai.
5. M2 + M3 trim dormant LLM layer; use native LangChain structured output.
6. Cleanups: delete mockData.ts (L1), reuse org_scoped (M8), single discount constant (L5), rename ToolCall (L3), extract ShortfallAlert (L2).

## On our ai/nexus specifically
The design we built is sound: integer-paise, text-only LLM, MatchingClient seam, LangGraph functional API fit the sequential flow. The critique is NOT the design; it is that it duplicates the mechanism the backend already has (LLM seam, settings, agent pattern) and ships as a non-packaged folder wired by sys.path. Highest-value follow-ups: M5 (package it) and M4/M6 (reuse backend LLM/secrets infra) so the two tracks stop drifting.
